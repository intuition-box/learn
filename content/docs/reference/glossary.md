---
title: Glossary
description: Definitions of the terms used throughout this documentation.
---

| Term              | Definition                                                                                                                                                                                                                                                       |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Account           | An address that creates terms or holds shares. Intuition Core keys accounts by wallet address, and attributes each API write to the account of the key that made it.                                                                                             |
| Agent skill       | A package of reference material that a coding agent loads when a task needs it. See [Agent skills](../agents/agent-skills.md).                                                                                                                                   |
| API key           | A credential for a node's query API. It begins with `ik_` and is bound to an account, to which every write made with it is attributed. The node stores only its SHA-256 hash.                                                                                    |
| Artifact          | A typed record that an enrichment plugin attaches to an atom, such as OpenGraph data or a Wikipedia extract. Core stores artifacts in `kg.artifacts`.                                                                                                            |
| Artifact type     | The name of a kind of artifact, such as `opengraph` or `npm-package`. Each artifact type has a registered data schema.                                                                                                                                           |
| Atom              | The basic unit of data. An atom identifies one thing. Its identifier is derived from its data. See [Atoms](../concepts/atoms.md).                                                                                                                                |
| Atom data         | The bytes that define an atom: a URL, an IPFS URI, a JSON document, a plain string, or raw bytes.                                                                                                                                                                |
| Atom services     | A stateless HTTP service that classifies and enriches input without storing it. See [Atom services](../build/atom-services.md).                                                                                                                                  |
| Atom wallet       | A smart contract wallet that the protocol associates with each atom. The `AtomCreated` event records its address.                                                                                                                                                |
| Bonding curve     | The function that sets the price of a vault's shares. On the default curve, the share price rises only as fees accumulate in the vault. On a progressive curve, it rises as more shares are issued. See [Vaults and signals](../concepts/vaults-and-signals.md). |
| Checkpoint        | The record of the last event a projection processed. After a restart, the projection resumes from its checkpoint.                                                                                                                                                |
| Classification    | The stage that determines what an atom refers to, expressed as a domain and a subtype, such as `github` and `repo`. Plugins perform it.                                                                                                                          |
| Counter-triple    | The term that represents disagreement with a triple. It has its own identifier and vault.                                                                                                                                                                        |
| Curve ID          | The number that identifies a bonding curve in the `BondingCurveRegistry` contract. A term has a separate vault on each curve. On mainnet, curve ID 1, the Linear Curve, is the default.                                                                          |
| Deposit           | A transfer of TRUST into a term's vault in exchange for shares. A deposit is a signal.                                                                                                                                                                           |
| Enrichment        | The stage that gathers metadata about an atom from external sources and stores it as artifacts.                                                                                                                                                                  |
| ERC-8004          | An Ethereum standard that defines onchain registries for the identity, reputation, and validation of autonomous agents. See [ERC-8004 agent layer](../agents/erc-8004.md).                                                                                       |
| Event store       | The database that holds the append-only log of chain events and the read models built from it.                                                                                                                                                                   |
| Explorer          | The dashboard included with Intuition Core. It reads a node's query API. See [Explorer](../node/explorer.md).                                                                                                                                                    |
| Identifier        | A 32-byte value that names a term, derived from the term's content. See [Identifiers](../concepts/identifiers.md).                                                                                                                                               |
| Identity strength | How an enrichment plugin found a resource: by an external `identifier`, by a direct `url`, or by a `title` search. A title search is the weakest of the three.                                                                                                   |
| Indexer           | The component of Intuition Core that decodes `MultiVault` events into the event store.                                                                                                                                                                           |
| Indexing scope    | The set of choices that decide what a node ingests, projects, processes, and serves. See [Indexing scope](../extend/indexing-scope.md).                                                                                                                          |
| Intuition Core    | The open-source backend: an indexer, projections, workers, a query API, atom services, and an explorer.                                                                                                                                                          |
| Knowledge graph   | The database that holds atoms, triples, accounts, predicates, and artifacts.                                                                                                                                                                                     |
| Lease             | A time-limited claim that a worker holds on an atom while it runs one stage. If the worker stops, the lease expires and another worker claims the atom.                                                                                                          |
| MultiVault        | The protocol contract that registers terms and holds their vaults.                                                                                                                                                                                               |
| Node              | An instance of Intuition Core. In the knowledge graph's schema, `nodes` is also the name of the table that holds atoms.                                                                                                                                          |
| Parse             | The first processing stage. It determines what form an atom's data takes, such as a URL, a JSON document, or an ENS name.                                                                                                                                        |
| Plugin            | A module that adds classification or enrichment coverage to a node. The built-in plugins use the same interface as yours. See [Classification plugins](../extend/classification-plugins.md).                                                                     |
| Position          | The shares an account holds in one term's vault on one curve.                                                                                                                                                                                                    |
| Predicate         | An atom that names the relationship a triple expresses. See [Predicates](../concepts/predicates.md).                                                                                                                                                             |
| Preset            | A named set of choices. An enrichment preset selects plugins, such as `default` or `music`. An indexing scope preset selects events, projections, and processing, such as `kg-only`.                                                                             |
| Projection        | A process that builds a read model from the event store and records its progress in a checkpoint.                                                                                                                                                                |
| Query API         | Intuition Core's REST API, which serves the knowledge graph and accepts writes. See [REST API](../build/rest-api.md).                                                                                                                                            |
| Read model        | A table that a projection derives from chain events, such as `vault` or `position`.                                                                                                                                                                              |
| Redemption        | The return of shares to a vault in exchange for TRUST.                                                                                                                                                                                                           |
| Share             | A unit of ownership in a vault. A deposit issues shares and a redemption returns them. The bonding curve sets their price.                                                                                                                                       |
| Signal            | A deposit into a term's vault, read as a public statement that the depositor stands behind the term. A deposit on a counter-triple signals disagreement with the triple.                                                                                         |
| Term              | An atom or a triple. Every term has an identifier and, once registered, a vault.                                                                                                                                                                                 |
| Triple            | A claim that links a subject, a predicate, and an object. See [Triples](../concepts/triples.md).                                                                                                                                                                 |
| Trust provider    | An organization that publishes assessments of ERC-8004 agents into the graph.                                                                                                                                                                                    |
| TRUST             | The native currency of the Intuition network. On the testnet it is tTRUST.                                                                                                                                                                                       |
| Vault             | The pool, held by `MultiVault`, into which TRUST is deposited for a term on one curve. See [Vaults and signals](../concepts/vaults-and-signals.md).                                                                                                              |
| Workers           | The Intuition Core services that parse, classify, and enrich atoms, one stage each.                                                                                                                                                                              |
